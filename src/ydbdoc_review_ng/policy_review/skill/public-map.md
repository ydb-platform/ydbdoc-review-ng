# Карта публичной документации YDB в GitHub

Снимок: **2026-11-25**, `ydb-platform/ydb`, ветка `main`, commit **`367e36d46fc570dc7b7345e3427b48cfa86f2fda`**. Источник публикации: `ydb/docs`, языки `ru` и `en`, сайт `ydb.tech/docs`. Это карта структуры исходников, не подтверждение состояния опубликованного сайта.

## Источники и границы

- [Корневой RU TOC](https://github.com/ydb-platform/ydb/blob/367e36d46fc570dc7b7345e3427b48cfa86f2fda/ydb/docs/ru/toc.yaml), [общее RU-меню](https://github.com/ydb-platform/ydb/blob/367e36d46fc570dc7b7345e3427b48cfa86f2fda/ydb/docs/ru/core/toc_i.yaml), [EN-меню](https://github.com/ydb-platform/ydb/blob/367e36d46fc570dc7b7345e3427b48cfa86f2fda/ydb/docs/en/core/toc_i.yaml), [конфигурация](https://github.com/ydb-platform/ydb/blob/367e36d46fc570dc7b7345e3427b48cfa86f2fda/ydb/docs/.yfm).
- Физическая основа статей: `ydb/docs/{ru,en}/core/`. Публичный `ydb/docs/{ru,en}/overlay/toc_p.yaml` также участвует в композиции. Наличие слова `overlay` в GitHub само по себе не означает внутреннюю документацию.
- Корневая цепочка: `{lang}/toc.yaml` → `core/toc_m.yaml` → `overlay/toc_p.yaml` → унаследованные `toc_i.yaml` и тематические TOC. Меню составлено из `include`, а не из дерева каталогов.
- Назначения разделов ниже сверены с их вводными статьями, оглавлениями и примерами: `concepts/index.md`, `devops/index.md`, `dev/index.md`, `analyst/index.md`, `security/index.md`, `contributor/index.md`, `reference/index.md`, `recipes/index.md`, `troubleshooting/index.md`, `concepts/backup.md`, `reference/configuration/feature_flags.md`. Все пути относительно `core/` и той же ревизии.
- Общее поведение OSS, в том числе доступное внутренним пользователям, имеет источник здесь. Общий алгоритм не становится внутренним из-за текущего места хранения или примера с внутренним endpoint.

## Основные разделы и их назначение

Пути в таблице относительны к `ydb/docs/{ru,en}/core/`. Это правила выбора места при ревью, сформулированные по назначению существующих разделов. Наличие старой неподходящей статьи не служит разрешением повторять её размещение.

| Раздел меню RU / EN | Источник навигации / путь | Что сюда относится | Когда нужен другой раздел |
|---|---|---|---|
| Оглавление / Contents | `index.yaml`, корневой `toc_i.yaml` | Обзор и навигация по документации | Самостоятельная инструкция, определение или справочник |
| Начало работы / Quick start | `quickstart.md` | Короткий первый успешный запуск, минимальный вход для нового пользователя | Полный рабочий регламент, исчерпывающий каталог параметров |
| Концепции / Concepts | `concepts/toc_p.yaml` → `concepts/toc_i.yaml` | Механизм, модель, гарантии, ограничения, состояния и последствия, понятные новому читателю | Самостоятельный план выполнения пользовательской задачи, внутренний регламент |
| Администрирование кластеров / Cluster Administration | `devops/toc_p.yaml` | Требования, выбор конфигурации, развёртывание, обслуживание и наблюдаемость кластера; здесь допустимы профильные концепции и пошаговые руководства администратора | Инструкция пользователю приложения; политика внутренних сервисов Яндекса |
| Для разработчиков приложений / For Application Developers | `dev/toc_p.yaml` | Проектирование схемы, использование возможностей, разработка приложений и сквозные руководства для этой роли | Полная спецификация API; отдельный узкий рецепт, которому есть подходящий раздел в «Рецептах» |
| Для аналитиков и инженеров данных / For Analysts | `analyst/toc_p.yaml` | OLAP-сценарии, датасеты, практические аналитические руководства и ограничения | Универсальный справочник SQL или эксплуатация кластера |
| Для инженеров безопасности / For Security Engineers | `security/toc_p.yaml` | Аутентификация, авторизация, аудит, шифрование, настройка безопасности; профильные объяснения и инструкции | Внутренние роли ABC, служебный порядок получения доступа, не являющийся общим поведением YDB |
| Для контрибьюторов / For Contributors | `contributor/toc_p.yaml` → `toc_i.yaml` | Устройство реализации OSS, разработка ядра, сборка, тестирование, изменения документации | Пользовательская семантика функции или внутренний процесс команды с закрытыми инструментами |
| Справка / Reference | `reference/toc_p.yaml` | Контракты: синтаксис, параметры, значения, ответы, API, команды, форматы и настройки; локальные примеры их применения | Самостоятельный сценарий с выбором метода и последовательностью действий |
| Рецепты / Recipes | `recipes/toc_p.yaml` | Ограниченная практическая задача: исходные условия, действия и проверяемый результат | Концептуальные гарантии; полный административный жизненный цикл; реакция на инцидент |
| Диагностика проблем / Troubleshooting | `troubleshooting/toc_p.yaml` | Симптом → диагностика → интерпретация → устранение или дальнейшие действия | Обычный сценарий использования без диагностической цели |
| Вопросы и ответы / Questions and answers | `faq/toc_p.yaml` → `toc_i.yaml` | Короткий ответ на частый вопрос со ссылкой на основной материал | Полная копия справочника, длинный самостоятельный учебник или регламент |
| Загрузки / Downloads | `downloads/toc_p.yaml`, `downloads/toc_i.yaml` | Дистрибутивы, SDK и другие доступные загрузки | Объяснение поведения продукта |
| Публичные материалы / Public materials | `public-materials/toc_p.yaml` → `toc_i.yaml` | Выступления, статьи и другие внешние материалы | Каноническое описание контракта вместо ссылки на презентацию |
| Список изменений / Changelog | `toc_changelog.yaml` | Версионные изменения и release notes | Постоянная инструкция по использованию возможности |

В RU дополнительно присутствуют условные внешние группы **«Обучение»** и **«Карьера»**, `when: audience != "tech"`. Их нет в корневом EN TOC этого снимка. В RU «Загрузки» расположены до «Публичных материалов», в EN порядок обратный. Не объявлять локали структурно идентичными и не добавлять EN-пункты автоматически.

## Состав тематических разделов на дату снимка

### Концепции

`concepts/toc_i.yaml`: глоссарий; аналитические возможности; потоковая обработка; архитектура; соединение с БД; схемные объекты; топология; выполнение запросов; транзакции; вторичные индексы; CDC; TTL и вытеснение; сжатие; ограничения; резервное копирование и восстановление; асинхронная репликация; bridge; трансфер данных.

Вложенные ветви находятся в `concepts/analytics/`, `streaming-query/`, `architecture/`, `datamodel/`, `query_execution/`, включая федеративные запросы и S3. Пояснение гарантий backup/restore принадлежит концепции. Самостоятельный алгоритм миграции или рекомендация, какой метод копирования выбрать для таблицы, проверяется как практическое руководство/рецепт.

### Администрирование

`devops/toc_p.yaml`: **Концепции**, **Управление конфигурацией кластера**, **Способы развёртывания**, **Enterprise Manager**, **Наблюдаемость**, **Резервное копирование и восстановление**, **Первоначальная синхронизация асинхронной репликации**.

Подразделы: `devops/concepts/`; `configuration-management/` с V1, V2 и миграцией; `deployment-options/` с Ansible, Kubernetes и ручным развёртыванием; `enterprise-manager/`; `observability/`; `backup-and-recovery/`; `async-replication-initial-sync.md`. Пошаговая настройка кластера здесь уместна: нумерация не отправляет все инструкции в «Рецепты».

### Разработка приложений и аналитика

`dev/toc_p.yaml`: начало работы; потоковые запросы; примеры приложений; генерация кода из YQL; туториал YQL; первичный ключ; партицирование; вторичные, векторные, полнотекстовые, JSON и локальные индексы; гибридный поиск; оптимизация запросов; пакетная загрузка; постраничный вывод; таймауты; системные представления; CDC; разделяемый читатель топика; Terraform; пользовательские атрибуты; управление потреблением ресурсов.

Ветви с собственными TOC: `dev/streaming-query/`, `example-app/`, `yql-tutorial/`, `primary-key/`, `tables/`, `local-indexes/`, `optimization/`.

`analyst/toc_p.yaml`: быстрый старт OLAP; импорт датасетов (`analyst/datasets/`); практические руководства (`analyst/practical-guides/`, включая SCD); ограничения. У аналитической инструкции есть собственное ролевое место, её не нужно переносить только из-за практического жанра.

### Рецепты и диагностика

`recipes/toc_p.yaml`: резервное копирование (`recipes/backup/`), SDK и фреймворки (`recipes/ydb-sdk/`), CLI (`recipes/ydb-cli/`), YQL, векторный и полнотекстовый поиск, поиск по JSON, локальные индексы, трансфер, потоковые запросы.

SQL-рецепты физически находятся в **`yql/reference/recipes/`**, но включаются в «Рецепты» через соответствующий TOC. Не требовать переноса в `recipes/` только из-за префикса пути. Короткий пример синтаксиса на странице команды остаётся примером справки.

`troubleshooting/toc_p.yaml`: производительность (`performance/`), spilling (`spilling/`), примеры диагностики, расхождение времени клиента и кластера. `faq/toc_i.yaml`: общие вопросы, SDK, ошибки, YQL, аналитика, известные проблемы, все вопросы на одной странице; есть условные и скрытые пункты.

### Контрибьюторы и безопасность

`contributor/toc_i.yaml`: работа над изменениями; сборка и тесты Ya; логирование; релизы; документация; **Ядро** (акторная система, распределённое хранилище, метаданные, LocalDB, Hive, DataShard, конфигурация V2, bridge, spilling, нагружающие акторы); тестирование/хаос-тесты.

`security/toc_p.yaml`: аутентификация и MFA; авторизация; начальная настройка; аудит; шифрование; краткая запись управления доступом. Наличие объяснения механизма внутри ролевого раздела допустимо, если оно служит его задаче.

## Как применять и обновлять

Применять вместе с [классификацией абзацев](documentation-placement.md). Перед замечанием открыть реальный TOC и соответствующий подраздел в ревизии PR. Сохранять условия `when`, `hidden`, порядок включений и различия RU/EN; записанный граф не является списком одновременно видимых страниц.

Карта не включает структуру отдельных проектов Yandex Cloud, Yandex Query, корпоративной документации или самостоятельной документации YQL. У них другие корни и публикации. Если PR затрагивает их, явно сообщить, что эта карта их не покрывает.

Обновление карты выполняется отдельным явным действием: получить новые ревизии, перечитать оглавления и характерные статьи, изменить назначения только при подтверждённом изменении, обновить дату, SHA и индекс разделов, проверить классификационные сценарии. Не переписывать карту автоматически под текущий PR, чтобы устранить замечание о размещении.
