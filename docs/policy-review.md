# Проверка документации в GitHub Actions

Действие `.github/actions/policy-review` запускает агента с [публичной версией навыка pr-review](../src/ydbdoc_review_ng/policy_review/skill/SKILL.md). Агент получает сведения о PR, diff всех файлов, ограниченную выборку предыдущих замечаний и точные SHA. Он выбирает материалы для проверки и формулирует замечания. В отчёте есть результат, привязанные к строкам замечания с доказательствами и исправлениями, выполненные проверки и оставшиеся вопросы.

## Источники и инструменты

Версию навыка и публичных карт определяет SHA запущенного действия. Навык содержит хеш исходных инструкций. Отдельный ресурс writing-policy читает `ydb/docs/.ruler/DOCUMENTATION_POLICY.md` и три нормативных файла в объявленном порядке. Источником служит явно утверждённый `YDBDOC_REVIEW_RULES_SHA` или SHA базовой ветки PR. В отчёте агент указывает недоступные материалы.

Агент запрашивает окно до 120 строк файла или ищет литерал в одном указанном файле на HEAD или base tip. Инструменты работают только с публичным репозиторием YDB. Для исторических журналов доступны затронутые строки из diff. Хост исполняет вызовы GitHub и передаёт модели только результат чтения. Действие не запускает код PR.

Один запуск допускает до 24 ходов, 96 вызовов инструментов и 512 KiB сериализованного запроса на ход. Ответ модели ограничен 8192 токенами. Модель сама выбирает чтение или завершает ревью Markdown-ответом; структурированный finish_review также доступен. Когда оставшегося бюджета становится мало для дальнейшего чтения и финального ответа, хост отключает инструменты и запрашивает отчёт по уже собранным доказательствам. Последний разрешённый ход также отводится на отчёт. Принудительное завершение отмечается как неполная проверка; обязательный резерв стоимости сохраняется. Третье одинаковое чтение и вторая одинаковая неудачная операция останавливают цикл. Журнал содержит только имена инструментов, пути, диапазоны и статусы, без содержимого файлов. Общий комментарий публикует хост после повторной сверки HEAD. Он обновляет предыдущий комментарий приложения и создаёт Check на проверенном SHA. Свободный Markdown-ответ сам по себе не считается автоматическим подтверждением отсутствия замечаний.

## Допуск, бюджет и аудит

Workflow и finalizer для `ydb-platform/ydb` находятся в [examples](../examples). Gate проверяет автора через collaborators API. Внешнему автору требуется разрешение `ok-to-test` на текущий HEAD. Оператор метки `doc_review` должен иметь права write, maintain или admin. Перед запуском действие ждёт 300 секунд без новых коммитов и повторяет проверки допуска. Запись в YDB исключает одновременные платные проверки одного PR.

Действие использует установленный в проекте `deepseek-v4-flash` и версию тарифов. Перед каждой отправкой оно проверяет HEAD и владение запуском, вычисляет верхнюю оценку стоимости полного запроса и резервирует её в YDB. Лимит задаёт `YDBDOC_REVIEW_MAX_RUN_COST_RUB`. Ноль отключает платные вызовы. Пропущенное или недопустимое значение останавливает запуск. Неизвестная стоимость сохраняет резерв и блокирует следующую попытку до сверки. Публичная сумма обозначается как оценка по тарифу. Ответы подставного провайдера в тестах не измеряют расходы или качество настоящего ревью.

Gate, запуск и finalizer проверяют скачанный код и ресурсы по Git tree разрешённого тега. Аудит сохраняет фактический SHA действия, способ исполнения на доверенном runner, модель, версию тарифов и расход попыток. Finalizer восстанавливает прерванный запуск из ledger. Для GitHub, публикации, модели и YDB используются существующие входы composite action. Хост устанавливает зависимости из публичного PyPI с обязательной проверкой хешей по `docker/review-requirements.lock`.

## Локальная проверка

`pytest tests/policy_review/test_skill_launcher.py -s` проводит публичный PR 60931 через настоящий launcher с подставными GitHub, YDB и провайдером, выводит размеры сериализованных запросов и резервы.

Команда `ydbdoc-review review --snapshot INPUT --output REPORT` сохраняет существующую автономную формальную проверку snapshot без обращения к модели.

## Подключение и восстановление

1. На доверенной машине с доступом к audit YDB создайте таблицы командой `python -m ydbdoc_review_ng.policy_review.commands init-schema --file docs/doc-review-schema.sql`.
2. Consumer PR workflow и finalizer используют `.github/actions/policy-review@v1.0.1`. Для чтения GitHub, проверки участников, меток, Check и общего комментария они передают штатный Actions token. Finalizer также использует разрешение actions read.
3. В review job передаются `YANDEX_CLOUD_API_KEY_DOC_REVIEW`, `YANDEX_CLOUD_FOLDER_DOC_REVIEW` и `YDB_SA_KEY`. Переменные `YDB_ENDPOINT`, `YDB_DATABASE` и `YDB_TOKEN` позволяют выбрать другой экземпляр аудита. Шаблоны проверяют `YDBDOC_REVIEW_ENABLED == 'true'`. Лимит платного запуска независимо определяется переменной бюджета.
4. При смене HEAD начинается новое ожидание. Повторное событие для уже принятого HEAD не отменяет первоначальную работу. После завершения или отмены Actions run finalizer проверяет его статус, имя и тип события. Если остался резерв с неизвестной стоимостью, сопровождающий сверяет расход перед освобождением lease.
