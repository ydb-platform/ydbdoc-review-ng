# Вопросы для согласования

На момент создания черновика ответы ещё не получены.

| № | Вопрос | Рекомендация для первой версии |
|---|---|---|
| Q-01 | Отдельная repo означает отдельную от ydb или также от реализации? | Код, требования и знания в ydbdoc-review-ng |
| Q-02 | Какой бюджет одного запуска в RUB? Нужны ли дневной/общий с переводами лимиты? | Отдельный run limit; сумма задаётся заказчиком, дневной лимит обсуждается |
| Q-03 | Общий комментарий или замечания к строкам; блокировать ли merge? | Review comments, suggestions и общий отчёт; информационный пилот |
| Q-04 | Проверять новые коммиты автоматически? | Да; прежнюю попытку останавливать |
| Q-05 | Внешнему автору нужно новое разрешение на новый SHA? | Да, с сохранением разрешения на уже одобренный SHA |
| Q-06 | Нужны ли автоматические коммиты грамматики из GENERAL_RULES? | Suggestions; расхождение с автоисправлением явно согласовать |
| Q-07 | Проверять ли draft PR сразу? | Дождаться ready_for_review |
| Q-08 | Только новые нарушения или вся изменённая статья? | Читать статью целиком; замечания по нарушениям, введённым PR |
| Q-09 | RU и EN или только одна локаль? | Обе; отчёт на русском |
| Q-10 | Нужна ли в MVP полная визуальная проверка правила 13? | Отмечать отсутствие проверки до выбора механизма |
| Q-11 | Где запрещено тире по правилу 15? | Согласовать знаки и исключения для Markdown, кода, URL, CLI и диапазонов |
| Q-12 | Используем существующую ok-to-test вместо ok-2-test? | Да, одна метка для CI |
| Q-13 | Какой срок хранения текстов, расходов и approvals? | Тексты ограниченный TTL; финансовый аудит отдельно |
| Q-14 | Что считать уполномоченным ручным оператором? | Collaborator с write/maintain/admin; не общий allowlist переводчика |

Q-01–Q-06 влияют на архитектуру/пользовательское поведение и заданы в чате.
Остальные вопросы могут быть уточнены при согласовании перед внедрением.
Предлагаемые значения не являются ответами заказчика.
